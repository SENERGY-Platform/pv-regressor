# pv-regressor


## Input

The weather fields come from the import `import-open-meteo-previous-runs`, one
message per forecast. Radiation and precipitation for `forecasted_for` = `H` are the mean and
the sum over the preceding hour `[H - 1 h, H)`; the other variables hold at `H`. Any of the nine
variables may be `null`.

| key                        | type   | description                                                                 |
|----------------------------|--------|-----------------------------------------------------------------------------|
| `shortwave_radiation`      | float  | Global horizontal irradiance, mean over the hour before `forecasted_for`, W/m² |
| `direct_radiation`         | float  | Direct horizontal irradiance, mean over the hour before `forecasted_for`, W/m² |
| `diffuse_radiation`        | float  | Diffuse irradiance, mean over the hour before `forecasted_for`, W/m²         |
| `direct_normal_irradiance` | float  | Direct normal irradiance, mean over the hour before `forecasted_for`, W/m²   |
| `cloud_cover`              | float  | Cloud cover at `forecasted_for`, %                                          |
| `temperature_2m`           | float  | Air temperature at `forecasted_for`, °C                                     |
| `relative_humidity_2m`     | float  | Relative humidity at `forecasted_for`, %                                    |
| `precipitation`            | float  | Precipitation sum over the hour before `forecasted_for`, mm                 |
| `wind_speed_10m`           | float  | Wind speed at `forecasted_for`, km/h                                        |
| `forecasted_for`           | string | Valid time `H` of the forecast, RFC 3339 UTC                                |
| `issued_at`                | string | Issue time of the forecast, RFC 3339 UTC                                    |
| `lead_days`                | int    | Lead of the forecast in days                                                |
| `energy`                   | float  | El. power generated by the PV system, in W                                  |
| `energy_time`              | string | Timestamp of `energy`; optional, see below                                  |

The weather input maps exactly the twelve weather fields. The PV input maps `energy` and
`energy_time`, or `energy` alone for a device without a time field; training then uses the time
the platform stored with the value. Live PV values are not used, history is read for training.

## Output

One row per weather message, for the hour that forecast describes. Messages whose nine variables
are all `null`, and forecasts for hours already over, produce no row.

| key             | type          | description                                                                                         |
|-----------------|---------------|-----------------------------------------------------------------------------------------------------|
| `output`        | float or null | Forecast mean PV power in W over the hour starting at `timestamp`; `null` during the initial phase |
| `timestamp`     | string        | Start of that hour, UTC, plus less than one second, see below                                     |
| `initial_phase` | string        | Message whether and how long the operator is in the initialization/training phase; empty once a model exists |

A forecast for valid time `H` yields `timestamp` = `H - 1 h`, the start of the hour its radiation
values describe. Each hour gets one row per lead (with `lead_days` [1, 2]: one a day ahead, one two
days ahead). The microseconds of `timestamp` grow as the lead shrinks, so the most recent forecast
for an hour sorts last.

## Training and persistence

The operator uses the ML lifecycle from the current `operator_lib` release
specified in `pyproject.toml`.
Historic weather and PV inputs are loaded from TimescaleDB or Kafka as Ray
datasets. Training joins each forecast for valid time `H` to the mean measured
PV power of `[H - 1 h, H)`, the hour its radiation describes. Exact duplicate
weather rows are dropped first. The features are the sun elevation in the
middle of that hour, the nine weather variables and the lead in hours
(`forecasted_for - issued_at`). Preprocessing and scikit-learn fitting execute
on a Ray worker.

The fitted preprocessing pipeline and regressor are registered together in
MLflow. The `production` model alias is used for inference. Consequently,
operator-local files are neither the source of training data nor the model
registry, and restarts do not discard the trained model.

The training parameters are fixed in `main.py` and are not part of the config:
90 days of history, a new training every 24 hours, a retry after 6 hours when a
training fails or finds too little data, and at least 168 hours of matched
weather and PV data.

Until the first model is trained, every forecast is answered with `output` set
to `null` and `initial_phase` stating the approximate remaining time.

## Weather input

The weather input is an instance of the import
`import-open-meteo-previous-runs` at the location of the PV system, with
`lead_days` [1, 2] and `start` 90 days back. On its first start the import backfills forecasts from `start`, so a new
instance can train as soon as the PV history covers 168 matched hours.

The import topic keeps only a few days. History beyond that needs an export of
the import, created before the import first starts and holding a column for
each of the twelve weather fields, `issued_at` included; the deployment then
reads the weather history from the export. Without one it reads the import
topic, which holds less than the 168 hours training needs unless its retention
is longer.

Weather data by [Open-Meteo.com](https://open-meteo.com/), licensed
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). The free Open-Meteo
API is for non-commercial use only.

## Manifest

The interface is declared in `main.py` (`PVInputs`, `ForecastOutputs`,
`CustomConfig`). `uv run python -m operator_lib manifest main.py` writes
`operator-manifest.json` from it; the CI does so before every release and
commits it. Once `operators/pv-regressor.json` in `platform-content` names this
repository as its `source_repository`, the platform reads inputs, outputs and
config of a version from the manifest at its tag.

## Development

Install the locked environment with `uv sync`. Run the operator with
`uv run --locked python main.py` and the tests with
`uv run --locked pytest -q`. VS Code can use the included debug configuration; deployment-specific environment variables are read from the
git-ignored `.env` file.
