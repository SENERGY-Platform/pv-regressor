# pv-regressor


## Input
| key                                       | type                                                 | description                                                                                                |
|-------------------------------------------|------------------------------------------------------|------------------------------------------------------------------------------------------------------------|
| `instant_air_temperature`                 | float                                                | Forecast air temperature at `forecasted_for`, in °C                                                        |
| `instant_relative_humidity`               | float                                                | Forecast relative humidity at `forecasted_for`, in percent                                                 |
| `instant_ultraviolet_index_clear_sky`     | float                                                | Forecast clear-sky UV index at `forecasted_for`                                                             |
| `1_hours_precipitation_amount`            | float                                                | Forecast precipitation in the hour starting at `forecasted_for`, in mm                                      |
| `instant_cloud_area_fraction`             | float                                                | Forecast cloud cover at `forecasted_for`, in percent                                                        |
| `weather_time`                            | string                                               | Time of the weather import message, identical for all rows of one forecast                                  |
| `forecasted_for`                          | string                                               | UTC target timestamp of the forecast                                                                         |
| `energy`                                  | float                                                | El. power generated by PV-system; in Watt                                                                  |
| `energy_time`                             | string                                               | Timestamp of PV-power value `energy`                                                                       |

## Output 

| key                | type                                                 | description                                                                       | 
|--------------------|------------------------------------------------------|-----------------------------------------------------------------------------------|
| `output`           | float or null                                        | Forecast PV-power value for time specified by `timestamp`; `null` during the initial phase |
| `timestamp`        | string                                               | Timestamp specifying PV-power forecasting time                                    |
| `initial_phase`    | string                                               | Message whether and how long the operator is in the initialization/training phase; empty once a model exists |

## Config options

| key                | type                                                 | description                                               | required |
|--------------------|------------------------------------------------------|-----------------------------------------------------------|----------|
| `lat`              | float                                                | latitude of PV-system                                     | yes      |
| `long`             | float                                                | longitude of PV-system                                    | yes      |
| `logger_level`     | string                                               | `info`, `warning` (default), `error`, `critical`, `debug` | no       |

## Training and persistence

The operator uses the ML lifecycle from the current `operator_lib` release
specified in `pyproject.toml`.
Historic weather and PV inputs are loaded from TimescaleDB or Kafka as Ray
datasets. Training joins each weather forecast to the mean measured PV power of
the hour identified by `forecasted_for`; the forecast lead time is retained as
a model feature. Preprocessing and scikit-learn fitting execute on a Ray worker.

The fitted preprocessing pipeline and regressor are registered together in
MLflow. The `production` model alias is used for inference. Consequently,
operator-local files are neither the source of training data nor the model
registry, and restarts do not discard the trained model.

The training parameters are fixed in `main.py` and are not part of the config:
90 days of history, a new training every 24 hours, a retry after 6 hours when a
training fails or finds too little data, and at least 168 hours of matched
weather and PV data.

Until the first model is trained, every forecast batch is answered with
`output` set to `null` and `initial_phase` stating the approximate remaining
time.

## Weather input

The weather input is provided by
[import-yr-forecast](https://github.com/SENERGY-Platform/import-yr-forecast).
Its `max_forecasts` config must be 48, the number of rows the operator collects
per forecast; with the import's default of 1, no forecast batch is ever
complete. `weather_time` is mapped from the import message time, which is the
same for all rows of one MET forecast and therefore identifies the batch.

## Manifest

The interface is declared in `main.py` (`PVInputs`, `ForecastOutputs`,
`CustomConfig`). `uv run python -m operator_lib manifest main.py` writes
`operator-manifest.json` from it; the CI does so before every release and
commits it. Once `operators/pv-regressor.json` in `platform-content` names this
repository as its `source_repository`, the platform reads inputs, outputs and
config of a version from the manifest at its tag.

## Development

Install the locked environment with `uv sync`. Run the operator with
`uv run --locked python main.py`. VS Code can use the included debug
configuration; deployment-specific environment variables are read from the
git-ignored `.env` file.
